# NumSharp `np.*` signatures against NumPy 2.4.2

Generated by `tools/api-parameter-parity/signature_diff.py` from `dump_modules.cs`: every `[ModuleName]` module
of NumSharp.Core and the object API `np.random.Generator`, and (with `--types`, the second pass) NumPy's other
classes as their C# types (`np.matrix` -> `NDMatrix`, `np.ma.MaskedArray` -> `NDMaskedArray`, the bit
generators, ...), constructors as `(constructor)`, extension methods, and the typed `NDArray<T>`. NumPy's
parameters come from its runtime signature, completed from its `.pyi` stubs and numpydoc sections where that
signature forwards `(*args, **kwargs)`. Do not edit it by hand; rerun the tools. The
script's docstring has the full rules. In short: NumPy has ONE signature per function, so a name with several
C# overloads differs by that alone (the owner's rule of 2026-10-17: "one whole api per function as numpy
provides, remove others"); the CLOSEST overload, the one the fewest edits away from NumPy's signature, is what
the single surviving overload must become, and its parameters are diffed: positional-only by slot,
positional-or-keyword by name and slot, keyword-only by name. `*args` needs a `params` array; C# parameters
that NumPy takes through `**kwargs` are not differences.

Kinds: **missing** (NumPy has it, no overload does), **in another overload only** (the closest overload lacks
it, another overload has it: merging fixes it), **renamed** (another name at that slot), **extra** (C# only),
**slot** (a positional parameter elsewhere: a positional port binds the wrong argument), **C# requires** (NumPy
defaults it: a port that omits it does not compile), **default** (two different values), **varargs** (`*args`
as fixed parameters, no `params` array; often forced, because a C# `params` array must come last and nothing
optional may follow it, so NumPy's keyword-only parameters after `*args` cannot share its signature), **null
default** (one side None/null: often C#'s spelling of "not given", same behavior unless a probe says
otherwise), **policy** (missing but excluded by the parity plan §3: `like`, `subok`, a ufunc's `casting` /
`order` / `signature`, the field `order` of the sorts, `einsum_call`).
