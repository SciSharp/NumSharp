# NumSharp 0.81.0

This release moves NumSharp to NumPy 2.5.4, gives its functions NumPy's own signatures and brings NumPy's scalars, every Python and NumPy exception class, and 17 new np.* functions.
An NDArray now shares its memory with TorchSharp tensors, in both directions.

### 🧭 Overview
- NumPy 2.x API coverage around 96.2%, everything except datetime, complex64 and other exotic dtypes is fully supported, with byte-to-byte equality and compatibility to NumPy.
  - NumPy's scalars - a 0-d result is NumPy's read-only scalar, an element read `a[i, j]` returns one, and NumPy's 36 scalar classes are callable (`np.float64(1.5)`, `np.int8("12")`).
- **NumPy 2.5.4 is the reference** (0.80.0: NumPy 2.4.2) - every oracle test case is NumPy 2.5.4's answer, with NumPy 2.5's behavior across linear algebra, random, numpy.ma, `np.fft`, text, sorting, reductions and dtypes, its keyword-only `descending=` sort, and NumPy 2.5.4's own OpenBLAS in **NumSharp.Interop.OpenBLAS**.
- **Fresh results laid out as NumPy's** - ufunc results take NumPy's trivial-loop C / F or NpyIter K layout down to the strides of length-1 axes, keepdims reductions and `np.median` lay out as NumPy's, and every zero-size array has NumPy's all-zero strides.
- **NumSharp on phones** - proven end to end on two Android phones with ONNX Runtime's CPU, XNNPACK and NNAPI providers: an XNNPACK session's outputs now import without a copy, and float-to-int casts on Mono run 4.5-5.7x faster with NumPy's bytes.
- **New documentation** - the TorchSharp, Exceptions and NumPy Scalars pages, and a diagram of NumSharp's 18 released integrations opening the README and the Interoperability page.
- **36 NumPy-parity, memory-safety and tooling fixes**, **2 measured speedups** and **20 breaking changes**, across the release's 237 commits.
- **1 new NuGet package** - **NumSharp.Interop.TorchSharp**.
- **1,122,248 NumPy 2.5.4 oracle test cases** (0.80.0: 1,119,305 NumPy 2.4.2 cases) and 21,115 test methods (0.80.0: 20,506).

### 📦 New NuGet Packages
- **NumSharp.Interop.TorchSharp** - zero-copy interop between `NDArray` and [TorchSharp](https://github.com/dotnet/TorchSharp)'s tensors in both directions, with `Auto` / `View` / `Copy` modes.

### 📦 New NuGet Packages

One optional companion package ships for the first time, co-versioned with **NumSharp** (it depends on **NumSharp**). It converts arrays between NumSharp and TorchSharp, with no engine backend and no native asset of its own (it calls the libtorch that TorchSharp loads), so Core stays 100% managed without it.

- **NumSharp.Interop.TorchSharp** - zero-copy interop between `NDArray` and [TorchSharp](https://github.com/dotnet/TorchSharp)'s `torch.Tensor` (the .NET bindings for libtorch, the engine under [PyTorch](https://pytorch.org)), in both directions and without Python.
  - Modes - every verb takes `Auto` (a view when the dtype and the layout allow it, else a copy; the default), `View` (shares memory or throws, naming what prevents the view) or `Copy` (always independent).
  - Export - `AsTensor` hands the array's buffer to libtorch: every non-negative-stride layout (contiguous, sliced, transposed, stepped) crosses as the same strided tensor, a broadcast of writeable memory as torch's own `expand`, and libtorch releases the buffer when the last tensor over it is freed; `ToTensor` copies.
  - Import - `AsNDArray` views a CPU tensor's storage through its own `detach()`, so the view survives `set_` and the tensor's `Dispose`; `ToNDArray` copies; a tensor that requires grad, and an expanded one, import read-only (`t.detach().AsNDArray()` is the writeable route).
  - Dtypes - the ten dtypes both sides share cross as themselves; uint16 / uint32 / uint64 / char / decimal export by NumPy's NEP 50 promotion (int32 / int64 / float64 / int32 / float64), and an explicit `dtype` converts under NumPy's casting rule (`same_kind` by default); complex64 and bfloat16 tensors import widened exactly under `Auto` / `Copy`; a reversed view, a read-only array, a sparse, conjugated or non-CPU tensor copies under `Auto`; text arrays and quantized or meta tensors are refused in every mode.
  - Checks - `MayShareMemory` tells whether a result shares the source's memory, `ToScalarType` / `ToDType` map the dtypes, and live export / import counters help leak checks.
  - Proven - a state matrix holds 45 array states x the ten shared dtypes x the three modes to NumPy 2.5.4's flags and `torch.from_numpy`'s layout, and 24 tensor states to `Tensor.numpy()`, with the deliberate differences asserted (read-only, misaligned and off-16-byte complex128 arrays copy where `from_numpy` shares).
  - Depends - [TorchSharp](https://www.nuget.org/packages/TorchSharp) 0.100.0 or later, the managed package only, with no upper bound (tested on 0.100.0 and 0.107.0); you reference the libtorch flavour you run (`TorchSharp-cpu` or a CUDA package).

### 💥 Breaking Changes
- NumPy's parameter names (calls that name the old ones must be renamed): `np.transpose(a, axes)` (was `premute`), `np.array_equal(a1, a2)`, `np.iscomplex` / `isreal` / `iscomplexobj` / `isrealobj(x)`, `np.isscalar(element)`, `np.array_repr(arr)`, `np.cumsum` / `np.cumprod(a, axis, dtype, out)` (were `arr` / `typeCode`), `reshape(shape)` (was `newShape`), `np.unravel_index(indices, shape)`, `np.ravel_multi_index(multi_index, dims, mode)`, `np.insert(arr, obj, values)`, `np.tensordot(a, b, axes: (a, b))` (were two lists), `np.ma.default_fill_value(obj)`, `np.ma.size(obj)` and `MaskedArray.clip(min, max)` - `a8bedd23`, `a4e65776`, `54b4cada`, `ac04f166`, `be0ea187`.
- Removed names: `np.round_` (use `np.round`), `np.average_returned` / `np.ma.average_returned` (`returned: true`), `np.indices_sparse` (`sparse: true`), the generic `np.zeros<T>` / `ones<T>` / `empty<T>` / `full<T>` / `argsort<T>` / `finfo<T>` / `iinfo<T>` / `can_cast<TFrom, TTo>` (pass the dtype), `NDArray.Normalize()` and `AxisOutOfRangeException` - `a8bedd23`, `a4e65776`, `4be864e0`, `54b4cada`, `21578726`, `be0ea187`.
- Calls that no longer compile: `np.zeros(shape, 'F')` (name `order: 'F'`; NumPy reads that letter as a dtype), `np.tile(a, 2, 2)` (`np.tile(a, (2, 2))`), `np.random.random_sample(2, 3)` / `rand(Shape)` (`random_sample((2, 3))` / `rand(2, 3)`), `astype(t, false)` (`astype(t, copy: false)`), `np.frexp(x, m, e)` (`out: (m, e)`), `np.ma.array(data, mask)` (name `mask:`), `np.ma.reshape(a, 2, 3)` (a tuple), `np.fft.fftfreq` with a float `n`, `dtype.newbyteorder('>')` (`">"`), an `object`-typed value to `np.insert` / `np.append`, and a method group of a unary ufunc (`Select(np.exp)` needs a lambda) - `a4e65776`, `cff912ae`, `1a23575c`, `4be864e0`, `54b4cada`, `76d682e2`, `be0ea187`.
