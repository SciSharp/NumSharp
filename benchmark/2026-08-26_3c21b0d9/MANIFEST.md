## Methodology
- **C#:** BenchmarkDotNet, `OfficialBenchmarkConfig` — InProcessEmit toolchain, 50 measured
  iterations / 5 warmup, iteration time capped at 25 ms. MemoryDiagnoser on.
- **NumPy:** time-budgeted per op — a ~200 ms window (a >20 ms/call op runs exactly 100 times), 10 warmup (warm long-lived interpreter).
- **Timing basis:** best window (min) of each side's per-case sweep — min-based harnesses run
  each case to a ~200 ms time budget (a >20 ms/call op runs exactly 100 times); the C# op-matrix
  keeps BenchmarkDotNet's 50 iterations. merge-results.py compares the mins; per-case means are
  retained in the JSON (`numpy_mean_ms`/`numsharp_mean_ms`) as interference/tail diagnostics.
- **Sizes:** 1,000 / 100,000 / 10,000,000 elements. Same seeds both sides.
- Join keyed on (op, dtype, N, scenario); effective timing is the fastest valid backend profile.
- **Availability:** MissingBackendException and NotSupportedException are recorded, never timed.
- **Backend profiles:** Managed C# and OpenBLAS are merged into the canonical matrix.
- **Subsystems** appended to `benchmark-report.md`: NDIter, Layout, Operand, Cast, Fusion.
