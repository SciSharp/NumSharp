# numpy.polynomial Chebyshev points and Gauss-Chebyshev quadrature (U8) — NumSharp vs NumPy 2.4.2

Generated by `benchmark/polynomial/polypts_report.py` from a `polypts_bench.cs` run. **NPY/NS = NumPy time /
NumSharp time — higher is better, > 1 means NumSharp is faster.** Every cell's result was compared byte for
byte (SHA-256 of dtype, shape and data; both slots of chebgauss) against NumPy's before it was timed: all 35 cells are bit-exact.

Method: both sides pinned to the same two P-cores (`NS_PROBE_AFFINITY=0x14`), never concurrently; C# in Release
with `DOTNET_TC_CallCountingDelayMs=0` and a drained tier-1 warm-up (warm, sleep, warm again); best-of-rounds
per side. Every node is the C runtime's sin / cos on both sides (about 4.5 ns), so the large counts measure what
NumPy spends around it: its int64 ramp, its intermediate arrays and its Python statements.
Host: Intel64 Family 6 Model 183 Stepping 1, GenuineIntel, Windows 11.

chebpts1 computes half its sines: its ramp is antisymmetric and the C runtime's sin is odd bit for bit, so each
sine's negation fills the mirrored slot (the same bytes as one sin per element). chebpts2 and chebgauss have no
exact pairs, so their 10K cells sit at the cos floor: there NumPy's extra passes are cache-resident and nearly free,
and both sides spend about 5.5 ns per node in the same C runtime cos (NumSharp's managed call is ~10% slower per
element than NumPy's C loop), which caps the ratio near 1.2x.
