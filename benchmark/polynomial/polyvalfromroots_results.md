# numpy.polynomial.polynomial.polyvalfromroots (unit 6) — NumSharp vs NumPy 2.4.2

Generated by `benchmark/polynomial/polyvalfromroots_report.py` from `polyvalfromroots_bench.cs` runs. **NPY/NS =
NumPy time / NumSharp time — higher is better, > 1 means NumSharp is faster.** Every cell's result was compared byte
for byte (SHA-256 of dtype, shape and data) against NumPy's before it was timed: all 65 cells are bit-exact.

Method: both sides pinned to the same two P-cores (`NS_PROBE_AFFINITY=0x14`), never concurrently; C# in Release with
`DOTNET_TC_CallCountingDelayMs=0` and a drained tier-1 warm-up; best-of-rounds per side
and, over 3 alternating NumPy / NumSharp runs, each side's minimum per cell (a background burst on the
host only ever adds time).
NumPy computes `np.prod(x - r, axis=0)`: an `x - r` temporary of nr times the result, then the reduction's nr
multiply passes (or its reduce loop over the roots). NumSharp runs one pass: each point reads its roots once and
writes its value once, the products in NumPy's own order and form.
Host: Intel64 Family 6 Model 183 Stepping 1, GenuineIntel, Windows 11.
