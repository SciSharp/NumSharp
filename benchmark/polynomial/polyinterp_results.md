# numpy.polynomial chebinterpolate (U9) — NumSharp vs NumPy 2.4.2

Generated by `benchmark/polynomial/polyinterp_report.py` from a `polyinterp_bench.cs` run. **NPY/NS = NumPy time /
NumSharp time — higher is better, > 1 means NumSharp is faster.** Every cell's result was compared byte for byte
(SHA-256 of dtype, shape and data) against NumPy's before it was timed: all 27 cells are bit-exact.

Method: both sides pinned to the same two P-cores (`NS_PROBE_AFFINITY=0x14`), never concurrently, OpenBLAS at ONE
thread on both sides (NumPy under `OPENBLAS_NUM_THREADS=1`, NumSharp through `NumSharp.Interop.OpenBLAS`, the same
scipy-openblas build); C# in Release with `DOTNET_TC_CallCountingDelayMs=0` and a drained tier-1 warm-up;
best-of-rounds per side. Both sides time the whole call, the interpolated function included (a Python lambda on
NumPy's side, a C# delegate on NumSharp's). NumPy's time at low degrees is its Python statements (chebvander's loop
over the degree, np.dot's argument conversion, the two divisions); at high degrees the (deg + 1)**2 matrix dominates
both sides — chebvander writes it (NumPy row by row, a ufunc call per row; NumSharp in one kernel) and the product
reads it — so the ratio falls from ~16x at degree 100-200 toward the memory cost of that matrix.
Host: Intel64 Family 6 Model 183 Stepping 1, GenuineIntel, Windows 11.
