# numpy.polynomial Gauss-Legendre / -Laguerre / -Hermite quadrature (U8) — NumSharp vs NumPy 2.4.2

Generated by `benchmark/polynomial/polygauss_report.py` from `polygauss_bench.cs` runs. **NPY/NS = NumPy time /
NumSharp time — higher is better, > 1 means NumSharp is faster.** Every cell's two result slots were compared byte
for byte (SHA-256 of dtype, shape and data) against NumPy's before it was timed: all 46 cells are bit-exact
(the degree-1000 Hermite cells included, whose nodes and weights hold NaN: the NaN payloads match too).

Method: both sides pinned to the same two P-cores (`NS_PROBE_AFFINITY=0x14`), never concurrently, OpenBLAS at ONE
thread on both sides (NumPy under `OPENBLAS_NUM_THREADS=1`, NumSharp through `NumSharp.Interop.OpenBLAS`, the same
scipy-openblas build); C# in Release with `DOTNET_TC_CallCountingDelayMs=0` and a drained tier-1 warm-up;
best-of-rounds per side, and the per-cell best over 3 alternating NumPy / NumSharp run pairs.
Host: Intel64 Family 6 Model 183 Stepping 1, GenuineIntel, Windows 11.

**The eigvalsh ceiling.** Every function is NumPy's statements around ONE `np.linalg.eigvalsh` call on the
companion matrix of `[0]*deg + [1]`, and both libraries run that call through the same LAPACK `syevd`. The
`eigvalsh` columns time that call alone, on that matrix; `ceiling` = NumPy's whole call over NumSharp's eigvalsh
alone — the NPY/NS a function would reach if every statement NumSharp owns took no time. NumPy's time at low degrees
is its three `{p}val` calls (Legendre, Laguerre) or its three normalised Hermite recurrences (Python loops of
deg - 1 steps, five array statements each, where NumSharp runs one IL kernel). syevd's work grows as deg^3 and takes
over both calls from degree ~100, so the ratio falls toward the ceiling, and where the ceiling itself is under 1.5x
no composition can reach 1.5x.
